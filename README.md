# 로파워 (LawPower) — 회생/파산 사건관리 어드민

도원 Admin(`tg_m`, 불법사채 구제센터 통합 업무관리) 소스코드를 그대로 참고해 만든
**개인회생/개인파산 사건관리 어드민** 프로토타입입니다. **디자인 시스템(컬러 토큰, 컴포넌트,
레이아웃)은 도원 Admin과 동일**하게 맞추고, 기능만 회생/파산 도메인에 맞게 새로 설계했습니다.
현재는 전부 **가상의 샘플 데이터**로 동작하며, 실제 DB(Supabase 등)는 연결되어 있지 않습니다.

## v9 업데이트 — 관리필요 박스 전체 건수 표시, 재통화 안내문구 겹침 수정 (6차 정리 요청 반영)

**1) "관리가 필요한" 박스가 전체 건수를 다 보여주지 않던 문제**: DB관리·고객관리 상단의
"관리가 필요한" 박스가 뱃지에는 전체 건수(예: 22건)를 표시하면서 실제로는 가로 스크롤
카드를 12건까지만 잘라 보여줘, 나머지가 있는지 알아채기 어려웠습니다. 가로 스크롤(숨겨진
스크롤바) 카드 방식에서, 게시판처럼 세로로 전부 나열하고 박스 안에서 세로 스크롤(스크롤바
보임)되는 리스트 방식으로 바꿔 — 건수 제한 없이 전체가 스크롤을 통해 모두 보이도록
했습니다.

**2) 재통화 예정일 안내 문구가 옆 컬럼과 겹쳐 보이던 문제**: v8에서 표 글씨 세로쌓임
버그를 고치며 표 셀 전체에 `white-space: nowrap`을 기본 적용했는데, DB관리 표의
"재통화 예정일" 컬럼 안내 문구("미지정 → OOOO-OO-OO 제안(클릭해서 지정)")처럼 원래
한 줄에 다 들어가지 않는 긴 문구는 nowrap 때문에 줄바꿈되지 못하고 옆 담당자/상태
컬럼 위로 넘쳐 겹쳐 보였습니다. 이 문구에만 다시 줄바꿈을 허용(`whitespace-normal`)해
컬럼 안에서 자연스럽게 2줄로 접히도록 수정하고, 컬럼 폭도 조금 넉넉하게 넓혔습니다.

## v8 업데이트 — UI 세로쌓임 버그, 피벗 토글, 정산설정 분리, 업무일정 캘린더 등 5차 정리 요청 반영

**1) 텍스트 세로쌓임(줄바꿈) 버그 수정**: DB관리 등 데스크톱 표 레이아웃이 화면 너비에 따라
컬럼이 좁아질 때, `white-space: nowrap` 보호 규칙이 모바일 미디어쿼리(`max-width:767px`)
안에만 있어서 그 경계를 벗어난 화면(가로모드, 큰 화면 폰, 창을 좁힌 데스크톱 브라우저 등)
에서는 이름·연락처 같은 글자가 한 글자씩 세로로 줄바꿈되는 문제가 있었습니다.
`app/globals.css`의 `.admin-responsive-table th, td` 규칙을 화면 너비와 무관하게 항상
적용되도록 바꿔, 모바일(안드로이드/아이폰) · 데스크톱 어디서든 글씨가 항상 가로 한 줄로
표시됩니다.

**2) DB관리 피벗칩 토글**: 상담가능시간 등 피벗 칩을 클릭해 필터링한 뒤, 같은 칩을 다시
클릭하면 선택이 해제되고 "전체"로 돌아가도록 했습니다.

**3) 리드정보 한 줄 표시**: 채무총액·소득·상담시간 태그가 2줄로 줄바꿈되던 것을, 한 줄로
나열하고 넘치면 가로 스크롤되도록 바꿨습니다(스크롤바는 보이지 않게 처리).

**4) 정산설정 독립 메뉴 + 결제방식 연동**: 예전에는 고객관리 안 팝업에서만 담당자×결제수단
요율을 조정할 수 있었는데, 사이드바에 "정산설정" 메뉴를 새로 만들어 관리자가 언제든 요율을
관리할 수 있게 분리했습니다. 또한 그동안 읽기전용으로만 표시되던 "결제방식"을, 고객관리
수정 화면에서 영업진이 실제로 드롭다운으로 선택할 수 있게 바꿨습니다 — 선택한 결제방식은
정산설정에서 설정한 요율과 자동으로 곱해져 **정산 메뉴의 "담당자별 정산 요약"에 예상
정산액 컬럼**으로 바로 반영됩니다.

**5) 대시보드 업무일정 캘린더**: 기존 분납/기일 캘린더 아래에 "업무일정 캘린더(DB 재통화
예정)"를 새로 추가했습니다. DB관리에서 지정한 재통화 예정일이 달력에 표시되고, 예정일이
지난 건은 "지남" 배지로 눈에 띄게 표시됩니다.

**6) DB관리·고객관리 상단 "관리가 필요한" 박스**: 도원 사채어드민의 "분납/상환일정 미등록"
박스와 같은 취지로, DB관리에는 재통화 예정일이 지났거나 아직 지정되지 않은 리드를,
고객관리에는 미수금은 남아있는데 분납일정이 하나도 등록되지 않은 의뢰인을 각각 상단에
가로 스크롤 카드로 모아 보여줍니다. 카드를 클릭하면 해당 건이 바로 필터링/선택됩니다.
이 어드민의 취지(① 관리자의 영업진 업무 모니터링, ② 영업진 스스로의 놓침 방지·효율적
고객 관리)에 맞춰, 관리자와 영업진 모두 "지금 무엇을 챙겨야 하는지"가 한눈에 보이도록
설계했습니다.

⚠️ 참고: 이번 라운드에서는 실제 소스 코드 반영에 집중했고, 정적 미리보기 이미지
(`dashboard-preview.html/png`)는 갱신하지 않았습니다 — 실제 동작은 `npm run dev`로 직접
확인해주세요.

## v7 업데이트 — 광고 인스턴트 양식, TM 영업 대시보드, DB 상담일지 등 4차 정리 요청 반영

**1) 광고 인스턴트 양식 필드 + 피벗**: 메타 광고 인스턴트 양식의 고정 질문 3종(채무 총금액·
실 월소득·상담가능시간)을 DB 리드 스키마에 고정 필드로 추가했습니다. DB관리 리스트에
색상 태그로 표시되고, 상단 피벗 바에서 각 카테고리(특히 요청하신 상담가능시간대)를
클릭하면 그 그룹의 리드만 걸러볼 수 있습니다. ⚠️ 예전에 쓰시던 "매일법률사무소 DB
구글시트 DB가공" 탭의 실제 색상표에는 접근할 수 없어, 카테고리가 한눈에 구분되도록
유사한 톤으로 새로 설계했습니다 — `lib/types.ts`의 `DEBT_RANGE_COLOR` /
`INCOME_RANGE_COLOR` / `CONSULT_TIME_COLOR` 값만 바꾸면 원하는 배색으로 바로
바뀝니다.

**2) 대시보드 — TM 영업 관점 지표**: 계약·분납 정보보다 오늘 해야 할 일이 먼저 보이도록
대시보드 맨 위에 당일 신규 DB, 전일 부재중, 5회 이하 컨택 부재율, 이번달 신규DB 대비
선임수·선임률 4개 지표와 "고려중 의뢰인 재설득 컨택 투두리스트"(재통화 예정일이 지난
순으로 정렬, 클릭하면 DB관리로 이동)를 추가했습니다. ⚠️ "전일 부재중"은 통화 시도
이력을 별도로 기록하는 콜 로그가 아직 없어 "어제 접수된 리드 중 현재 부재중 상태인
건수"로 근사했습니다 — 정확한 통화 이력이 필요하시면 콜 로그 테이블을 별도로 추가하는
작업이 필요합니다.

**3) 신청분류 → 상담 후 방향(개인회생/개인파산/워크아웃)**: DB 접수 시점에 미리 정하던
"신청분류"를 없애고, 상담원이 상담을 마친 뒤 방향을 고르는 "상담 후 방향"으로 시점과
명칭을 바꾸면서 워크아웃 옵션을 추가했습니다. 법원 사건(계약관리)은 여전히 회생/파산만
다루므로 계약관리 쪽 데이터 구조는 그대로 두었고, DB·고객 단계의 분류용 필드만
3종으로 넓혔습니다. 고객관리 상단 탭에도 워크아웃 필터가 추가됩니다.

**4) DB관리에서 상담일지 작성**: 이전에는 고객관리로 전환한 뒤에만 상담일지를 쓸 수
있었는데, 이제 DB 단계에서도 "상담일지 작성" 버튼으로 같은 화면(인적사항/소득현황/
재산현황/채무현황/변제계획/상담메모)을 바로 작성할 수 있습니다. 여기서 작성한 내용은
나중에 "고객 전환"을 누르면 그대로 고객관리로 승계됩니다. (내부적으로 고객관리 수정
팝업과 동일한 컴포넌트를 공유하도록 리팩터링해, 두 화면의 상담일지 UI가 항상 같게
유지됩니다.)

**5) 재통화 예정일 관리**: DB 리드마다 재통화 예정일을 지정할 수 있고, 비워두면
"접수일+1일"을 기본 제안값으로 보여줍니다. 예정일이 오늘이거나 지나면 리스트에서
바로 눈에 띄게 표시되고, 이 정보가 대시보드의 "고려중 재설득 투두리스트" 정렬 기준으로도
쓰입니다.

**6) 담당자 필터**: DB관리에 담당자별 필터를 추가해, 관리자가 전체 담당자 또는 특정
담당자의 DB만 골라볼 수 있습니다. ⚠️ 말씀하신 "담당자 배정 시 그 담당자 화면에서만
보이게"는 로그인 권한에 따라 접근 자체를 제한하는 기능이라, 이후 진행하기로 하신
권한 시스템(최고관리자/중간관리자/담당자별 열람·수정 권한) 작업 때 함께 구현하는 게
맞다고 판단해 이번에는 필터 기능까지만 넣었습니다. '상태' 값 목록 정리도 말씀하신 대로
이번엔 손대지 않았습니다.

**7) 계약금액/결제금액/미수금 3분할 표시**: 고객관리·계약관리의 목록과 상세 화면
전반에서 계약금액/결제금액/미수금 세 금액이 같은 용어로 일관되게 보이도록 정리했습니다
(계약관리 목록·고객관리 목록에 결제금액 컬럼을 추가하고, "기납부액"으로 불리던 곳도
"결제금액"으로 통일).

## v6 업데이트 — 서류안내문·정산요율·최저생계비 계산기 등 3차 정리 요청 반영

**1) 서류안내문 전송**: 고객관리 상세 화면(고객정보 클릭)에서 "서류안내문 전송" 버튼을 누르면
팝업이 뜨며, 도원 Admin의 '카카오톡 공지 생성' 기능을 참고해 만들었습니다. 서류체크리스트에서
아직 체크되지 않은 항목을 자동으로 뽑아 안내 메시지 초안을 만들어주고, 발송 채널(카카오톡
알림톡/SMS)과 수신 연락처를 선택해 전송할 수 있습니다. ⚠️ 카카오톡 알림톡/SMS 발송 API 연동
전이라 전송 버튼은 실제로 발송되지 않는 미리보기 화면이며, 실서비스 전환 시 API만 연결하면
그대로 동작합니다.

**2) 결제수단별 정산금 / 담당자별 정산요율 설정**: 결제수단(단순분납/로피분납/신카할부완납/
캐피탈분납)에 따라 정산금이 달라지고, 같은 결제수단이라도 담당자별로 다른 요율을 적용할 수
있어야 한다는 요청을 반영해 고객관리 상세 화면에 "정산 설정" 버튼(팝업)을 추가했습니다. 담당자
× 결제수단 표에서 요율(%)을 직접 입력하면 즉시 저장되고, 선택된 고객의 계약금액 기준 예상
정산금도 함께 보여줍니다. 위 두 버튼은 요청하신 대로 기존 고객정보수정/분납관리/전자계약서
버튼과 같은 자리(고객정보 클릭 시 뜨는 상세 화면)에 배치했습니다.

**3) 계약현황 표기 분리**: 고객관리 목록의 계약현황 컬럼이 "개인회생 · 진행중"처럼 한 덩어리로
보이던 것을, 요청하신 대로 **"계약분류 | 진행도"** 형태로 분리 표기하도록 바꿨습니다.

**4) 최저생계비 계산기(신규 메뉴)**: 가구원수별 최저생계비를 로펌 관리자가 직접 설정/관리하는
전용 메뉴를 새로 만들었습니다. 여기서 설정한 금액은 고객관리 수정 팝업의 변제계획 탭에서
가구원수를 입력하는 즉시 자동으로 반영됩니다(직접 수정도 가능). v5에서 설명드린 것처럼 이
수치는 법적으로 민감해 임의로 채워두지 않았으므로, 처음 사용 시 관리자가 최신 고시 기준을 한
번 입력해두어야 합니다.

**5) 메뉴 순서 조정**: 게시판 메뉴를 정산과 기간별 변동내역 사이로 옮겼습니다. 최종 순서는
대시보드 → DB관리 → 고객관리 → 계약관리 → 입금·분납 → 정산 → **게시판** → 기간별 변동내역 →
데이터집계 → **최저생계비 계산기** 입니다.

**6) 계약관리 유형/단계 표기 변경**: 박스(배지) 형식이던 유형·단계 컬럼을 요청하신 대로 일반
텍스트로 바꿨습니다(상태 컬럼의 배지는 유지).

**7) 고객관리 버튼/다운로드**: 목록 맨 우측 버튼을 "수정"에서 **"상세"**로 이름을 바꿨습니다
(클릭 시 뜨는 화면은 기존과 동일한 고객정보 수정 팝업입니다). 그 팝업 안에서 상담일지 전체
내용을 엑셀로 깔끔하게 내려받을 수 있는 **"고객 상담 엑셀 다운로드"** 버튼을 추가했습니다 —
처음 보내주셨던 상담일지 서식과 동일한 섹션 구성(인적사항/소득현황/재산현황/채무현황/변제계획
자동계산/상담메모)으로 `.xlsx` 파일이 즉시 생성/다운로드됩니다. ⚠️ 이 기능은 `xlsx`(SheetJS)
패키지를 새로 추가한 것이라, 실제 실행 전에 `npm install` 한 번이 필요합니다(아래 "처음 실행
하기 전에" 참고).

**8) DB관리 콜 횟수**: DB관리 리스트에 "콜 횟수" 항목을 추가했습니다. 처음엔 0에서 시작하고,
우측의 ▲▼ 버튼을 클릭할 때마다 숫자가 바로 증감합니다(별도 입력 없이 클릭만으로 기록).

**참고 — 지금은 최고 관리자 화면입니다**: 현재 만들고 있는 것은 모든 메뉴를 다 볼 수 있는 최고
관리자 페이지이고, 이후 로그인 권한별로 게시판 열람이나 수정 권한 등을 다르게 설정하는 작업은
별도로 진행 예정이라고 말씀해주신 내용 확인했습니다 — 이번 라운드에서는 별도로 구현하지
않았고, 다음 작업으로 남겨두었습니다.

## v5 업데이트 — 상담일지 반영 + 2차 정리 요청 반영

**1) 상담일지(개인회생·개인파산 상담일지) 전체 반영**
전달해주신 상담일지 엑셀 서식(인적사항/소득현황/재산현황/채무현황/변제계획 자동계산/상담메모)을
고객관리 **수정 팝업**에 8개 탭(기본정보/인적사항/소득현황/재산현황/채무현황/변제계획/상담메모/
서류체크리스트)으로 그대로 반영했습니다. 재산·채무 항목은 서식의 고정 행 구성(주택/토지, 임차
보증금, 예금/적금, 보험, 자동차, 퇴직금, 주식/펀드, 기타 / 세금체납, 건강보험체납, 담보채무(부동산·
자동차), 신용채무)을 그대로 사용했고, 5번 섹션의 자동계산 로직(월 가용소득 → 총변제예정액 → 청산
가치 비교 → 최종 변제금 → 탕감액/탕감률 → 진행가능여부)도 서식 그대로 구현해 입력하는 즉시
계산됩니다. 각 탭 하단에는 서식의 "상담 가이드" 체크포인트도 요약해 넣었습니다.

⚠️ **한 가지 양해 부탁드리는 부분**: 서식의 "최저생계비"(가구원수별)와 "소액임차인 최우선변제"
(지역별) 기준액은 매년/지역별로 고시가 바뀌는 법적으로 민감한 수치라, 임의의 표를 만들어 자동
판정하지 않았습니다. 최저생계비는 1인가구 기준값(1,538,543원, 전달주신 서식 원문 수치)만 참고로
채워두고 나머지는 상담원이 최신 고시를 확인해 직접 입력하도록 했고, 소액임차인 최우선변제는
자동조회 대신 참고 메모 필드로 남겨뒀습니다. 실서비스 전환 시 두 기준표를 법무팀에서 확정해주시면
자동화하겠습니다.

**2) 메뉴**: 도원 Admin과 동일한 구조로 **정산 / 기간별 변동내역 / 데이터집계** 3개 메뉴를 새로
추가했습니다. 사채업 전용 지표(환수, 연체율, 재약정성공률 등)는 로파워 도메인에 맞지 않아 계약매출·
실매출·미수금, 담당자별 실적, 최근 6개월 계약/결제 추이, 등록·수정·삭제 변동 로그로 대체했습니다.
(변동내역은 실제 DB가 없는 데모 특성상 새로고침하면 초기화됩니다 — 실서비스 전환 시 Supabase
트리거로 교체하면 영구 보관됩니다.)

**3) 대시보드**: 상단 연체 배너의 '실시간' 배지를 제거했습니다.

**4) DB관리**: 전환된 리드는 상태가 '전환 완료'로 표시되도록 라벨을 변경했고, 리스트에 '신청분류'
드롭다운(개인회생/개인파산)을 추가해 고객관리 상단 탭 분류에 사용하도록 했습니다. 이름 아래
'추정유형' 텍스트는 제거했습니다(신청분류 드롭다운으로 대체).

⚠️ 요청하신 옵션은 "개인회생/파산" 두 글자였는데, 화면 전체에서 이미 "개인파산"을 표준 표기로
쓰고 있어(사건유형 CaseType 자체가 '개인회생'|'개인파산') 일관성을 위해 '파산' 대신 '개인파산'으로
넣었습니다.

**5) 고객관리**: 목록 상단에 **개인회생/개인파산 필터 탭**을 추가해 DB관리에서 지정한 신청분류로
분류되도록 했고(계약관리 필터 패턴과 동일하게 '전체' 탭도 함께 넣었습니다), 페이지네이션을
**5명씩**으로 변경했습니다. 계약현황은 배지(칩) 대신 **일반 텍스트**로 표기하도록 바꾸고, 목록에
**계약금액·미수금** 컬럼을 명시적으로 추가했습니다. **수정 버튼을 누르면 도원 Admin처럼 팝업창이
뜨고**, 그 안에서 상담일지 전 항목 작성은 물론 계약 관련 메모(계약관리 사건 메모와 연동)와 서류
체크리스트 체크까지 한 화면에서 처리할 수 있습니다.

## v4 업데이트 — 메뉴/기능 1차 정리 요청 반영

디자인 골격(v3)을 유지한 채, 실제 사용 흐름에 맞춘 메뉴·기능 정리 요청을 반영했습니다.

- **메뉴**: DB관리·고객관리 위치를 도원 Admin과 동일하게 맞바꾸고(DB관리가 먼저), '사건관리'를
  '계약관리'로 명칭 통일. 일정관리 단독 메뉴는 없애고(대시보드 캘린더·사건상세 일정으로 충분),
  도원 Admin과 동일한 기능의 **내부 게시판**(공지 고정/순서, 검색, 파일 첨부)을 새로 추가
- **대시보드**: 계약·결제 추이, 미수금 추심 우선순위, 다가오는 기일·제출기한, 담당자별 실적
  카드를 제거해 화면을 더 간결하게 정리(핵심 KPI·분납/기일 캘린더·기간별 통계·구성비 차트는 유지)
- **고객관리**: 유입경로 필터·컬럼과 이메일 필드를 제거하고(메타광고 단일 채널이므로), 도원
  Admin처럼 **행을 클릭하면 하단에 고객 상세 패널이 열려** 분납관리·전자계약서·삭제까지 바로
  처리할 수 있도록 재구성. 컬럼 순서도 등록일·이름·연락처 순으로 통일
- **DB관리**: 시간대 구분과 재콜(카운트) 기능을 제거하고, 이름 표기를 '이름(저장형식)'에서
  순수 이름으로 단순화. 담당자는 자유입력 대신 드롭다운으로, 상태도 드롭다운 하나만 남기고
  그 아래 있던 상태 배지 박스는 제거
- **계약관리**: 메뉴명만 '사건관리'→'계약관리'로 변경(그 외 화면 구성은 동일)
- **입금·분납**: 목록에서 사건번호 컬럼을 제거(의뢰인명 기준으로만 검색)
- **공통**: 모든 목록의 이메일 필드를 제거하고, 등록일·이름·연락처가 함께 있는 목록은 이 순서로
  컬럼을 통일

**추가로 반영한 것** (요청 범위를 넘지 않는 선에서, 도원 어드민과 비교해 있으면 좋겠다고 판단한 것만):
- 고객관리 인라인 수정의 담당자 필드도 자유입력 → 드롭다운으로 통일(DB관리와 동일한 방식)
- 고객 상세 패널에 도원 Admin과 동일한 '삭제' 버튼 + 확인 모달(`ConfirmDelete`)을 추가해
  연결된 계약·분납 데이터까지 함께 정리되도록 함

## v3 업데이트 — 도원 Admin과 동일한 디자인으로 전면 재작업

이전 버전은 로피(LawFee) PG사 자료의 디자인(네이비/골드 톤, 로피식 카드·배지)을 참고해
만들었지만, **디자인은 도원 Admin과 완전히 동일하게, 기능만 다르게** 가져가기로 방향이
바뀌어 아래와 같이 전면 재작업했습니다.

- 컬러 토큰(navy/brand/gold 등 커스텀 팔레트)을 모두 제거하고, 도원 Admin과 동일하게
  **Tailwind 기본 팔레트(slate/blue/emerald/amber/red)만** 사용
- `components/ui/Primitives.tsx`에 도원 Admin `components/ui.tsx`의 Card/Button/Badge/
  PageHeader/Input/Select/Modal/SearchBox/StatusTabs/Pagination을 **그대로 이식**
- 사이드바(`components/layout/Sidebar.tsx`)를 도원 Admin과 동일한 구조(고정 248px 사이드바
  + 모바일 슬라이드 드로어, lucide-react 아이콘)로 교체 — 메뉴/브랜딩만 로파워에 맞게 변경
- 상단 헤더(`components/layout/Header.tsx`)를 신규 추가 — 고객 검색, 알림벨(연체 분납 +
  기일·제출기한), 신규 DB 펄스 배지 등 도원 Admin 헤더 기능을 회파산 도메인에 맞게 재구성
- 대시보드를 도원 Admin과 동일한 구조로 재구성: 기간 선택(DateRangePicker) + KPI 카드 4종 +
  **분납 캘린더 / 기일·제출기한 캘린더 듀얼 월간 캘린더**(날짜 호버 미리보기, 클릭 고정 팝업)
- 고객관리/DB관리/사건관리/입금·분납 목록 화면을 도원 Admin과 동일하게 **모바일 카드 리스트 +
  데스크톱 테이블**의 반응형 이중 레이아웃으로 재구성 (`admin-responsive-table` 포함)
- 사건 상세 화면을 도원 Admin의 고객 상세 패널과 동일한 정보 그리드(`bg-slate-50` 카드) 스타일로 재구성

이전 v2에서 추가했던 기능(직원1/2/3 데모 표기, DB관리 페이지, 게시판형 고객관리, 서류
체크리스트, 결제수단 필드, 전역 상태 스토어)은 그대로 유지됩니다 — 이번 업데이트는 **디자인
전면 교체**이며 기능 목록은 바뀌지 않았습니다.

## 중요 — 로컬에서 처음 실행하기 전에

이 코드는 npm 레지스트리 접근이 차단된 클라우드 샌드박스에서 **`npm install`/빌드를 한 번도
실행하지 못한 상태로** 작성되었습니다. TypeScript 컴파일러(strict 모드)로 문법·타입 오류는
자체 검증했지만, 실제 Next.js 빌드 파이프라인으로는 검증되지 않았으니 로컬에서 아래 순서로
실행하면서 혹시 나오는 사소한 오류(패키지 버전 궁합 등)는 확인해주세요.

```bash
npm install
npm run dev
# http://localhost:3000
```

Node.js 18.18 이상을 권장합니다.

## 기술 스택

- Next.js 14.2 (App Router) + React 18 + TypeScript (strict)
- Tailwind CSS 3.4 — 커스텀 토큰 없이 Tailwind 기본 팔레트만 사용(도원 Admin은 Tailwind 4를
  쓰지만, 기본 팔레트 값 자체는 동일해 시각적으로 같은 결과가 나오면서도 빌드 리스크가 낮은
  3.4를 유지했습니다. 정말 v4까지 맞추고 싶으시면 알려주세요.)
- `lucide-react` / `clsx` / `tailwind-merge` — 도원 Admin과 동일한 아이콘·클래스 병합 유틸
- 외부 차트 라이브러리 없음 — SVG 대신 순수 CSS(conic-gradient, flex 높이)로 도넛/막대 차트 구현
- 실제 백엔드 없음 — `lib/mock-data.ts`가 결정론적 시드(seed) 기반으로 의뢰인 64명·사건 78건·
  DB리드 34건·분납/일정 데이터를 생성합니다.

## 도원 Admin에서 그대로 가져온 것 / 로파워에 맞게 새로 설계한 것

**그대로 이식 (디자인)**
- 컬러 팔레트(slate/blue/emerald/amber/red), Card/Button/Badge 등 UI 프리미티브, 사이드바·
  헤더 레이아웃 구조, 모바일 카드/데스크톱 테이블 반응형 패턴, 월간 캘린더(호버+핀 팝업) UI

**회생/파산 도메인에 맞게 새로 설계 (기능)**
- 사건유형(개인회생/개인파산)과 9단계 절차 파이프라인(상담접수→…→종결)
- DB관리(상담 리드) → 고객 전환 흐름, 서류 체크리스트, 결제수단(단순분납/카드할부/로펌금융조합분납)
- 도원 Admin의 PG 정산·이폼사인 계약서·사채업체 조율 등 본업(불법사채) 전용 기능은 제외 —
  요청하신 대로 "회생/파산 사건 관리" 범위에만 집중

## 다음 단계 (실서비스 연동 가이드)

1. **DB 연동**: `lib/mock-data.ts`의 export들과 `lib/store.tsx`의 `setState` 호출부를
   Supabase 쿼리/뮤테이션으로 교체하세요. `lib/types.ts`의 인터페이스가 그대로 테이블 스키마
   초안으로 쓸 수 있게 필드명을 설계해뒀습니다.
2. **기존 도원 Admin과의 통합**: 디자인 시스템이 이제 동일하므로, 이 프로젝트를 도원 Admin
   저장소의 라우트 그룹(예: `app/(lawpower)/...`)으로 옮기면 `components/ui/Primitives.tsx`를
   도원 Admin의 `components/ui.tsx`로 그대로 바꿔치기할 수 있습니다 — 두 프로젝트가 같은
   컴포넌트 계약을 쓰기 때문에 병합 리스크가 낮습니다.
3. **인증/권한**: 현재 로그인·권한 분리가 없습니다(도원 Admin은 Supabase Auth 사용). 실사용
   전 담당자별 접근 제어가 필요합니다.
4. **민형사/사채 확장**: 이후 민형사·불법사채구제 사건까지 확장할 경우 `CaseType`에 유형을
   추가하고 유형별 절차 단계(`STAGE_LABELS`)만 새로 정의하면 대시보드/목록/상세 화면 구조는
   대부분 재사용 가능하도록 설계했습니다.
